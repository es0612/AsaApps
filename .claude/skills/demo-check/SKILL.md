# /demo-check - SNSデモ動画準備チェック＆修正スキル

AsaAppsプロジェクトのアプリをSNSデモ動画撮影可能な状態にするスキルです。
App#86-90の調査で発見された4つの問題パターンを自動チェックし、修正まで行います。

## 使い方

```
/demo-check AsaAppName
/demo-check 91        # アプリ番号でも可
```

引数がない場合はREADME.mdから最新のアプリを自動特定します。

## 実行手順

### Phase 1: アプリ特定と構造把握

1. 引数がアプリ番号の場合、README.mdからアプリ名を特定
2. `Apps/{AppName}/` のディレクトリ構造を把握
3. 以下のファイルを読む:
   - `project.yml`（デプロイメントターゲット、依存関係）
   - `*App.swift`（エントリーポイント、ModelContainer）
   - `ContentView.swift`（タブ構成、ナビゲーション）
   - 全ての ViewModel ファイル
   - Services/ 内の全ファイル
   - SampleDataGenerator があるか確認

### Phase 2: 4つのデモ問題パターンをチェック

以下の4パターンを**全て**チェックし、該当するものを報告する。

#### パターンA: ボタン未接続（空クロージャ）
- Views/ 内の全 .swift ファイルで `onStart: {}`, `onTap: {}`, `action: {}` などの空クロージャを検索
- `// TODO`, `// 将来実装` コメント付きの空アクションも対象
- `.disabled(true)` で無効化されたボタンも報告（軽微な問題として）

#### パターンB: DI接続漏れ（サービスアクセス不可）
- `getService()` や `getXxx()` メソッドが `nil` を返すパターンを確認
- ViewModel の `private let service` を子ビューから間接参照するコードがないか
- 子ビューが独自の ViewModel を初期化する際にサービスが渡されない箇所

#### パターンC: サンプルデータ不足（画面が空表示）
- **最頻出パターン**（5アプリ中4アプリで該当）
- 確認すべき3階層:
  1. **構造データ**: コース、プラン、ポートフォリオ等のメインコンテンツ → 投入されているか
  2. **履歴データ**: セッション履歴、認識履歴、取引履歴 → 投入されているか
  3. **統計データ**: ストリーク、正解率、合計時間 → UserProfile等に反映されているか
- ダッシュボード/統計画面が「0」や「データなし」表示になる箇所を全て洗い出す
- チャート・グラフが空になる条件を確認

#### パターンD: 外部サービスデータが0表示
- HealthKit、位置情報、カメラ等の外部サービスに依存する表示がないか
- シミュレータで取得不可能なデータに依存するサマリーカード/数値があるか
- 外部サービス未連携時の目立つUI要素（赤いボタン等）がないか

### Phase 3: 問題の修正

パターン別の修正テンプレート:

#### パターンA の修正
- `@State private var selectedXxx: Model?` を追加
- `.sheet(item:)` または NavigationLink で遷移先を接続

#### パターンB の修正
- ViewModel に `var xxxService: XxxProtocol { service }` アクセサを追加
- 子ビューの初期化コードを修正

#### パターンC の修正
- `Services/SampleDataGenerator.swift` を新規作成（または既存を拡充）
- 必ず含めるデータ:
  - メインコンテンツ（3-5件）
  - 使用履歴（過去1-2週間分）
  - ユーザー統計（リアルな数値）
  - お気に入り/ブックマーク（あれば）
- ViewModel の `loadInitialData()` でデータが空の場合に呼び出す

#### パターンD の修正
- `isDemoMode` フラグを ViewModel に追加
- `UserDefaults` でデモモードを永続化
- 外部サービス未連携時にダミー値を注入
- デモモード時に不要なUI要素（連携ボタン等）を非表示

### Phase 4: ビルド検証

```bash
cd Apps/{AppName}
xcodegen generate -s project.yml
xcodebuild -project {AppName}.xcodeproj -scheme {AppName} -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

ビルドエラーがあれば修正してリトライ。

### Phase 5: コミット

変更内容をコミット。メッセージ形式:
```
feat: {AppName} SNSデモ動画撮影準備

- [修正内容を箇条書き]

Co-Authored-By: Claude Opus 4.6 (1M context) <noreply@anthropic.com>
```

### Phase 6: デモ撮影フローの提案

修正後のアプリで推奨するデモ撮影フロー（画面遷移順）を提案する:
1. 起動直後の画面（第一印象）
2. メイン機能のデモ（最も映える操作）
3. データが充実している画面（ダッシュボード、統計等）
4. 詳細画面やインタラクション

## 出力形式

最終レポートは以下の形式で出力:

```
## {AppName} (App #{番号}) デモ準備完了 ✅

### チェック結果
| パターン | 結果 | 対応 |
|---------|------|------|
| A: ボタン未接続 | ✅/⚠️ | 修正内容 or 問題なし |
| B: DI接続漏れ | ✅/⚠️ | 修正内容 or 問題なし |
| C: データ不足 | ✅/⚠️ | 修正内容 or 問題なし |
| D: 外部データ0 | ✅/⚠️ | 修正内容 or 問題なし |

### 修正内容
- [箇条書き]

### デモ撮影推奨フロー
1. [画面と操作]
2. ...
```

## 重要な注意事項

- 必ず全4パターンをチェックする（1つでも漏れがあると撮影時に問題が発覚する）
- サンプルデータはリアルで自然な値にする（0や極端な値は避ける）
- 既存のユーザー体験には影響を与えない（デモデータは初回起動時のみ投入）
- ビルド成功を必ず確認してからコミットする
